1. 前置状态确认

开始前确认工作区保留着这 4 处源码改动（此前已清理过文档/门禁/冗余配置，这是最小可运行集）：

cd /home/zw/code/deepseek-harness
git status --short
# 预期输出：
 M packages/llm/llm-deepseek/package.json   # exports 加 ./wire 子路径（手写声明，工具不会生成）
 M pnpm-lock.yaml                            # workspace 安装记录
?? packages/llm/llm-deepseek/src/wire.ts    # wire 源文件（值导出：parseSse/serializeRequest 等）
?? packages/llm/llm-agent-hint/              # 插件本体（src/tests/配置）

关键依赖关系（谁离不开谁）：

文件作用缺失后果
src/wire.ts + package.json 的 ./wire exportagent-hint 以值导入方式引用 @deepseek-ai/dsh-llm-deepseek/wire（[adapter.ts:24-28]）Node 抛 ERR_PACKAGE_PATH_NOT_EXPORTED，插件加载即失败
tsdown.config.ts entry 含 wire构建产出 lib/wire.jsexports 映射落空，运行时找不到模块
exports 是手写的、唯一的源头。 仓库里 tsdown entry / files 数组 / check-workspace-constraints 全是围着 package.json 的 exports 转的"跟随者"。恢复运行能力时，exports 声明必须最先写回。

2. 构建（两步编译链）

本仓库的包没有独立的 build 脚本（package.json 里 scripts 为空，根目录的 pnpm build 是全仓 + 前端的大流程，不需要）。构建必须手动走两步：先 tsc 后 tsdown，顺序不能反——tsdown 的 entry 指向 tsc 的产物。

Step 1 — tsc 编译（产出 lib/types/*.js）

cd /home/zw/code/deepseek-harness
npx tsc -b packages/llm/llm-deepseek --force
npx tsc -b packages/llm/llm-agent-hint --force

# 验证产物：
ls packages/llm/llm-deepseek/lib/types/wire.js        # 应存在
ls packages/llm/llm-agent-hint/lib/types/index.js     # 应存在

--force 全量重编（增量模式下 wire.ts 曾出现不重编的情况，force 稳妥）。依赖包（cordis/llm 等）若有问题 tsc 会顺带报错。

Step 2 — 确认 tsdown entry 含 wire

检查 [tsdown.config.ts] 第 20 行 entry 是否为（缺 wire 就补上）：

entry: client ? '' : ['lib/types/{index,invariant,startup,wire}.js'],

Step 3 — tsdown 打包（产出 lib/wire.js、lib/index.js）

cd /home/zw/code/deepseek-harness
npx tsdown --env.DSH_BUILD_FACE host

# 验证产物：
ls packages/llm/llm-deepseek/lib/wire.js      # 应存在（exports ./wire 的落点）
ls packages/llm/llm-agent-hint/lib/index.js   # 应存在（插件入口）
为什么 tsdown 报 "Cannot find entry"： tsdown 一次构建整个 workspace（workspace: ['vendor/*', 'packages/*/*', 'apps/cli']）。如果 agent-hint 还没跑过 tsc（lib/types 为空），它会在解析阶段就失败——报错会指名 [@deepseek-ai/dsh-llm-agent-hint] Cannot find entry。解法就是回到 Step 1 先把两个包都 tsc 编译掉。

3. 安装检查

profile 安装是一次性的（此前已做过）。确认链接还在即可：

ls -l ~/.dsh/profiles/web/node_modules/@deepseek-ai/dsh-llm-agent-hint
# 应显示符号链接 → ../../../../../code/deepseek-harness/packages/llm/llm-agent-hint
# link: 安装不复制文件，产物永远实时指向源码目录，构建后无需重新安装

若链接不存在（例如 profile 被重建），重新安装：

cd /home/zw/code/deepseek-harness
pnpm dsh plugin --profile web add link:/home/zw/code/deepseek-harness/packages/llm/llm-agent-hint

出现 "declares no dsh.bundle — installed as a plain dependency" 警告是正常的（opt-in 插件本就不声明 bundle）。

4. 运行

4.1 启动观察服务器（先于 web）

# 已在跑则跳过（pgrep 无输出即未跑）
pgrep -af agent-hint-watch.mjs
nohup node /home/zw/code/agent-hint-watch.mjs > /home/zw/code/agent-hint-watch.log 2>&1 &

# 健康检查：
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:1026/v1/models   # 期望 200

可选环境变量：PORT（默认 1026）、VERBOSE=1（打印完整请求体）、UPSTREAM=...（转发真实 coordinator）。

4.2 启动 web

cd /home/zw/code/deepseek-harness
MOTOR_API_KEY=smoke-key pnpm dsh web
# 输出 "dsh web: http://127.0.0.1:3080" 且无插件加载报错即成功

4.3 配置三层自检（新环境才需要）

文件必须满足优先级说明
~/.dsh/settings.yamlagent-default-model.provider: deepseek-agent-hint最高——保存过的 UI 选择会覆盖 patch 默认值，这是"发消息没流量"的头号原因
~/.dsh/profiles/web/cordis.patch.yml含 llm-agent-hint 挂载（baseURL 指向 127.0.0.1:1026/v1）中——插件挂载与路由

两个文件都热重载，改完不用重启。快速验证组合树（不启动服务）：

cd /home/zw/code/deepseek-harness
MOTOR_API_KEY=smoke-key pnpm dsh web --dump-config 2>&1 | grep -A8 llm-agent-hint
# 能看到 provider: deepseek-agent-hint / baseURL: http://127.0.0.1:1026/v1 即正确

6. 停止与还原

# 停 web（用 -INT 优雅退出；-9 会跳过 teardown，stop 控制请求必发不出）
pkill -INT -f "bin.ts web"
pgrep -af "bin.ts web"          # 无输出 = 已退出

# 停观察服务器
pkill -f agent-hint-watch.mjs

# 清构建产物（保留源码，git 不跟踪 lib/）
rm -f packages/llm/llm-deepseek/lib/wire.js packages/llm/llm-deepseek/lib/types/wire.*
rm -rf packages/llm/llm-agent-hint/lib
产物删除后的影响： web 将无法加载该插件（exports 解析到不存在的 lib/wire.js）。源码、单测、静态阅读不受影响。下次要跑 web，回到第 2 节重新构建即可。

7. 故障排查

症状原因与解法
启动报 listen EADDRINUSE 127.0.0.1:3080 已有一个 web 实例占着端口（上次启动未停）。pkill -INT -f "bin.ts web" 优雅退出后再启动；pgrep -af "bin.ts web" 可先确认
tsdown 报 Cannot find entry: ["lib/types/{index,invariant,startup,wire}.js"] workspace 里某个包（报错会指名）还没跑 tsc，lib/types 为空。对指名的包先 npx tsc -b <包路径> --force 再重来 tsdown
tsc 增量编译后 wire.js 没产出 增量状态陈旧。加 --force 全量重编
web 启动报 ERR_PACKAGE_PATH_NOT_EXPORTED / 模块找不到 wire 三选一：① lib/wire.js 没构建（回第 2 节）；② package.json 的 ./wire export 被回退了（手写补回，3 处：exports./wire、files 两行）；③ tsdown entry 没恢复 wire
web 正常回复但观察服务器零流量 请求没走 agent-hint 路由。查 ~/.dsh/settings.yaml 的 provider 是否 deepseek-agent-hint，改完新建会话再发（旧会话锁定旧路由）
vitest 报 "No test files found" 在包目录里跑的。回到仓库根目录：pnpm exec vitest run packages/llm/llm-agent-hint
观察服务器 curl 不通 没启动或端口被占：pgrep -af agent-hint-watch 检查；重启见 4.1
缺 API key 报 MISSING_CREDENTIAL 启动 web 时没带 MOTOR_API_KEY=smoke-key（观察服务器不校验 key，但适配器在发请求前要求它存在）
